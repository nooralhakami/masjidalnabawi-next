# ما يحتاجه «دليل زوار المسجد النبوي» من خادم الهيئة

**إلى:** فريق التقنية في الهيئة.
**الغرض:** أن تصل تغييرات المشرف إلى كل الزوار خلال أقل من دقيقة. والتغييرات هي: إغلاق دورة مياه للصيانة، وأعمال المصاعد، وفتح مداخل سيارات المواقف وإغلاقها.
**الحجم:** خدمة صغيرة، ثلاث نقاط (endpoints) وسجل واحد. لا حسابات زوار، ولا بيانات شخصية، ولا مواقع.

## 1. الوضع الحالي
- الدليل موقع ثابت (static): HTML وJS وCSS وملفات JSON، يُبنى بالأمر `npm run build` في مجلد `dist/`، ويُستضاف على أي خادم ملفات.
- صفحة المشرف تظهر بكتابة «ADMIN» في البحث، ثم كلمة سر.
- **التغيير اليوم يبقى على جهاز المشرف وحده**، وكلمة السر تُفحص في المتصفح. هذا إخفاء لا حماية، ولهذا يُطلب الخادم.

## 2. المطلوب: ثلاث نقاط على النطاق نفسه
يُفضَّل أن تكون على نطاق الموقع نفسه (`/api/...`)، فلا يلزم CORS.

### أ. قراءة الحالة (للجميع)
```
GET /api/status
```
```json
{
  "version": 42,
  "updatedAt": "2026-10-16T21:30:00Z",
  "facilities": {
    "204": { "status": "maintenance" },
    "215": { "status": "works" },
    "216": { "status": "works", "worksBy": 215 }
  },
  "entrances": { "quba": false, "qurban": true, "east": false }
}
```
- **`facilities`:** المرافق التي تختلف حالتها عن بيانات الدليل فقط، فالمفتاح غير الموجود يعني الحالة الافتراضية.
  - `status`: إحدى `open` و`maintenance` و`works` (أعمال مصعد).
  - `worksBy`: يُضاف حين يُغلق مرفق بسبب أعمال المصعد في زوجه.
- **`entrances`:** `true` مفتوح و`false` مغلق، للمداخل `quba` و`qurban` و`east`.
- **`version`:** رقم يزيد مع كل تغيير.
- **الترويسات:** `Cache-Control: no-cache` مع `ETag`، ويُرد على `If-None-Match` بـ`304`.
- **الحِمل:** كل زائر يطلبها كل 30 ثانية تقريباً ما دامت الصفحة ظاهرة، والرد أقل من 5KB، وأغلب الطلبات `304`.

### ب. دخول المشرف
```
POST /api/admin/login      {"password": "..."}
```
- **صحيحة:** `204` مع كوكي جلسة `HttpOnly; Secure; SameSite=Strict`، مدتها 12 ساعة.
- **خاطئة:** `401`.
- **حد المحاولات:** 5 في الدقيقة لكل IP، وما زاد يُرد عليه بـ`429`.
- **كلمة السر:** تُحفظ في إعدادات الخادم مشفّرة (bcrypt أو argon2)، **ولا تكون في كود الواجهة أبداً.**
- **الخروج:** `POST /api/admin/logout`.

### ج. تغيير الحالة (للمشرف بعد الدخول)
```
PUT /api/status
```
```json
{
  "baseVersion": 42,
  "facilities": { "204": { "status": "open" } },
  "entrances": { "east": true }
}
```
- **ما يُرسَل:** ما تغيّر فقط. الواجهة نفسها تحسب أثر أعمال المصعد على الزوج وترسله.
- **التحقق:**
  - رقم المرفق من القائمة المعروفة (دورات المياه في `data/pois.json`).
  - `status` من القيم الثلاث.
  - المدخل من الثلاثة.
  - غير ذلك يُرد عليه بـ`400`.
- **التعارض:** إن كان `baseVersion` أقدم من الحالي (غيّر مشرف آخر قبله)، يُرد بـ`409` مع الحالة الحالية، فتعيد الواجهة العرض ويعيد المشرف المحاولة.
- **بلا جلسة:** `401`.
- **النجاح:** `200` مع الحالة الجديدة كاملة، بشكل رد (أ).

## 3. التخزين والسجل
- **الحالة:** سجل واحد (JSON) في أي قاعدة بيانات أو مخزن مفاتيح.
- **سجل التغييرات:** الوقت، وما تغيّر، والجلسة. يُرجع إليه عند الخطأ.

## 4. إن تعطّل الخادم
- تعمل الخريطة والمسارات كالمعتاد بالحالة الافتراضية أو آخر حالة وصلت.
- لا رسالة خطأ للزائر.
- المشرف يرى «تعذّر الحفظ» ويعيد المحاولة.

## 5. ما سنغيّره في الدليل بعد جاهزية الخادم
- إعداد واحد في `src/config/site.config.ts` يحمل عنوان الخدمة (مثل `STATUS_API: '/api'`). إن كان فارغاً بقي الدليل كما هو اليوم.
- **صفحة المشرف:** ترسل كلمة السر إلى `login`، وتُحذف بصمة كلمة السر من الواجهة.
- **الزوار:** يقرأون `GET /api/status` عند الفتح، ثم كل 30 ثانية.

## 6. فحص القبول
1. يغلق المشرف دورة مياه من جهاز، فتظهر مغلقة على جهاز آخر خلال دقيقة دون إعادة تحميل.
2. كلمة سر خاطئة 6 مرات في دقيقة: الأخيرة تُرد بـ`429`.
3. مشرفان يغيّران في اللحظة نفسها: لا يضيع تغيير، والثاني يرى `409` ثم يعيد.
4. إيقاف الخدمة: الخريطة تعمل، ولا خطأ يراه الزائر.
5. لا كلمة سر ولا مفتاح في ملفات `dist/`. يُتحقق بالبحث في الملفات.

## 7. الاستضافة نفسها
- **ملفات ثابتة من `dist/`** مع HTTPS.
- **`sw.js`:** بلا تخزين مؤقت (`Cache-Control: no-cache`).
- **ملفات `assets/`:** تخزين طويل (`max-age=31536000, immutable`)، لأن أسماءها تتغير مع كل بناء.
- **مرجع إعدادات Vercel الحالية:** `vercel.json` في المستودع.
- **الأرشيف:** المستودع `github.com/nooralhakami/masjidalnabawi-next`.
