### 2026-10-16 — المرحلة 3: محرك الخريطة (الصفحة الحقيقية)
**الطريقة:** `npm run perf`. نسخة البناء، بحجم Pixel 7، وCPU مبطأ 4×، وبلاطات بديلة. تُقاس ثلاث حركات: سحب (4 مرات)، وتقريب بالأزرار (6 مرات عبر طبقات العلامات)، وتدوير (12 مرة).
- **«JS لكل إطار»:** مجموع زمن استدعاءات `requestAnimationFrame` في الإطار الواحد، ومنها رسم MapLibre كله.

**اكتشاف في البيئة (لا في التطبيق):**
- طريق WebGL الافتراضي في Chromium هنا (Vulkan SwiftShader) يرسم البكسلات على خيط الصفحة نفسه.
- في سحبين فقط سجّل ملف الأداء 21.5 ثانية «(program)» أصلية، و211 مهمة طويلة حتى 347ms.
- مع `--use-angle=swiftshader` يجري الرسم في عملية GPU منفصلة، كما في الجوال الحقيقي، فنزل الرقم إلى 1 ثانية.
- صار هذا الخيار في `perf.mjs` وفي `playwright.config.ts`.

**النتيجة** (مرتان لكل حالة):
| الحالة | الإيماءة | JS/إطار p50 | p95 | مهام طويلة (أطولها) |
|---|---|---|---|---|
| أرضية MapLibre (الصورة الجوية وحدها، `PERF_QUERY=layers=base`) | سحب | 4.7 / 5.1 | 14.8 / 14.7 | 0 |
| | تقريب | 4.5 / 3.5 | 14.4 / 10.0 | 0 |
| | تدوير | 4.5 / 4.7 | 14.5 / 11.1 | 0 |
| الخريطة كاملة (324 مكاناً، 9 طبقات) | سحب | 7.8 / 8.0 | 19.3 / 16.7 | 0 |
| | تقريب | 10.8 / 8.1 | 31.7 / 35.3 | 1 (103 / 69ms) |
| | تدوير | 7.7 / 6.0 | 18.4 / 14.3 | 0 |

**القراءة:**
- **السحب والتدوير:** لا مهمة طويلة واحدة. Leaflet الحالي سجّل في الحاوية نفسها 11–15 مهمة طويلة عند التقريب.
- **علامات الأماكن:** تضيف نحو 2–4ms عند p50 فوق أرضية MapLibre.
- **حد «JS لكل إطار p95 ≤ 4ms مبطأ 4×»** (SPEC §6) **لا يتحقق، ولا تحققه MapLibre وحدها بلا أي علامة** (p95 بين 10 و15ms). القرار عند المالك (SPEC §9-11).
- **مهمة التقريب الطويلة:** سببها، حسب ملف الأداء، تحميل بلاطات الصورة الجوية الجديدة وفك ترميزها ورفعها (`fetch`، `createImageBitmap`، `Blob`)، لا كود العلامات.
- **زمن الإطار (150–330ms):** يقيس هنا العرض البرمجي على المعالج، فلا يُحكم به. الحكم على جهاز حقيقي.

**تجارب لم تُعتمد** (فروقها ضمن ضجيج القياس):
- بلاطات بيانات أكبر للأماكن (maxzoom 14–15، تقريب إحداثيات العرض حتى 13.6 سم).
- `fadeDuration: 0`.
- `setMaxParallelImageRequests(6)`.

**أُبقي:**
- رسم صور العلامات مسبقاً في أوقات الفراغ (`requestIdleCallback`)، حتى لا تُرسم دفعة واحدة عند التقريب.
- لا أي عمل لكل مكان في كل إطار. التصفية بـ`setFilter` فقط، ويتحقق e2e من أن تغيير الفلتر لا يرفع البيانات مرة أخرى.

### 2026-10-16 — قرار المالك وتحسين النقاط

- لا مهمة أطول من 100ms أثناء التقريب.
